# Task 23 Report: Pipeline SHA-256 Hashing

## Changes

- `downloadOnce` now seeds a SHA-256 hasher from an existing partial file on resume and hashes network bytes through `io.TeeReader` during the copy.
- Successful downloader attempts return their accumulated digest to `Download`, which writes the checksum sidecar without rereading the completed file.
- The complete-partial HTTP 416 path returns a digest computed from the existing partial file.
- YouTube stream copies now accumulate SHA-256 through `io.TeeReader`; direct stream downloads write the resulting digest after rename.
- Audio extraction and muxing continue to checksum their ffmpeg-produced final output with `WriteChecksum`, since those final bytes are not the downloaded stream bytes.
- `WriteChecksum` and `VerifyChecksum` remain available for existing-file integrity checks. A new `WriteChecksumDigest` helper writes a sidecar from a precomputed digest.

## Tests

- Added downloader coverage comparing the inline digest returned by `downloadOnce` with a sidecar generated by `WriteChecksum`.
- Added YouTube stream-copy coverage comparing its inline digest with a sidecar generated by `WriteChecksum`.
- Existing checksum, resume, and complete-partial tests continue to pass.
